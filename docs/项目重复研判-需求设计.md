# 项目重复研判功能需求设计

## 一、执行摘要

### 1.1 问题陈述
在招商引资项目管理中，多渠道数据来源（市级系统导入、园区手动填报）容易导致**同一项目在不同阶段被重复录入或阶段状态冲突**，造成：
- 数据冗余与不一致
- 统计失真（投资金额、项目数量虚高）
- 协作混乱（多部门跟踪同一项目但信息割裂）
- 决策误判（领导基于错误数据做决策）

### 1.2 解决方案
构建**AI驱动的智能判重系统**，在数据入库前自动识别潜在冲突，通过"研判池"集中展示待处理项目，提供**可视化比对界面 + AI辅助决策建议**，帮助投促局快速裁决数据冲突。

### 1.3 成功标准
- 判重准确率 ≥ 90%（基于历史冲突案例验证）
- 研判处理时效：平均每条记录 ≤ 3分钟完成裁决
- 数据去重率：系统上线后重复项目占比下降至 < 5%
- 用户满意度：研判人员操作便捷性评分 ≥ 4.5/5

## 二、用户体验与功能设计

### 2.1 用户角色定义

| 角色 | 权限范围 | 核心操作 |
|------|---------|---------|
| **区投促局管理员** | 全局查看所有研判记录、执行最终裁决 | 覆盖/忽略/视为新项目/合并覆盖 |
| **园区导入方** | 仅查看自己导入触发的冲突记录 | 查看比对详情、补充说明（不可修改裁决结果） |

### 2.2 用户故事

#### Story #1: 导入触发判重
> **作为** 园区招商人员，
> **我希望** 在Excel批量导入项目时系统能自动检测到与现有库的潜在冲突，
> **以便于** 我能及时了解哪些数据可能重复，避免无效工作。

**验收标准：**
- [ ] 导入时实时显示判重进度条（如："正在比对... 已检测3条冲突"）
- [ ] 冲突项目自动进入"待研判池"，非冲突项目正常入库
- [ ] 导入完成后生成《判重报告》，列出所有命中规则的项目及原因

#### Story #2: AI辅助比对分析
> **作为** 投促局研判人员，
> **我希望** 系统能自动对比冲突双方的关键字段差异（项目名称相似度、投资金额偏差、阶段状态矛盾等），
> **以便于** 我能快速判断是同一项目的不同版本还是完全独立的新项目。

**验收标准：**
- [ ] 提供**左右分栏对比视图**，左侧为"新导入数据"，右侧为"库中已有数据"
- [ ] 差异字段高亮标注（红色=冲突项，绿色=一致项，黄色=疑似相似）
- [ ] AI生成**研判建议文案**（如："项目名称相似度92%，投资主体相同，建议合并覆盖"）
- [ ] 支持点击字段查看**历史变更轨迹**（该字段在哪个阶段被谁修改过）

#### Story #3: 快速裁决操作
> **作为** 投促局管理员，
> **我希望** 对研判池中的项目能一键执行标准裁决动作，
> **以便于** 高效清理积压的冲突数据，保持系统数据纯净。

**验收标准：**
- [ ] 提供4种标准操作按钮：**覆盖** / **忽略** / **视为新项目** / **合并覆盖**
- [ ] 支持**批量裁决**（勾选多条后统一处理）
- [ ] 裁决后自动更新相关项目状态（如：覆盖后原项目升阶为新阶段）
- [ ] 所有裁决操作写入**操作日志**，支持追溯审计

## 三、AI智能判重规则体系（核心创新点）

### 3.1 判重规则设计原则

基于业务实际，我们设计了**四层递进式判重策略**：

| 层级 | 规则名称 | 命中条件 | 权重 | 说明 |
|------|---------|---------|------|------|
| **L1-强匹配** | 市级项目编码相同 | `新编码 == 库中编码`（编码为项目唯一标识） | ⭐⭐⭐⭐⭐ | **最高优先级规则**：同一市级编码视为同一项目，名称不同也可判定重复 |
| **L1-强匹配** | 项目名称完全相同 | `新名称 == 库中名称` (去除空格/括号) | ⭐⭐⭐⭐⭐ | 最高置信度，几乎确定重复 |
| **L2-高相似** | 项目名称模糊匹配 + 投资主体相同 | `相似度≥85% && 投资主体==` | ⭐⭐⭐⭐ | 极大概率重复 |
| **L3-中风险** | 投资主体相同 + 行业类别相同 + 投资金额偏差<20% | 多字段组合 | ⭐⭐⭐ | 需人工确认 |
| **L4-弱提示** | 联系人电话相同 或 地址高度重叠 | 单一弱特征 | ⭐⭐ | 仅提醒，不强制阻断 |

> **判重优先级**：市级项目编码 > 项目名称 > 字段组合 > 弱特征。导入数据带有市级编码时优先按编码判重；编码命中即视为同一项目，无需再看名称相似度。

### 3.2 阶段冲突矩阵（体现AI智能体的业务理解）

根据PRD 2.1.7的具体规则表，我们将其抽象为**阶段流转合理性校验**：

```
┌─────────────┬───────────┬───────────┬───────────┬───────────┐
│  导入目标    │  命中谋划库 │  命中在谈库 │  命中签约库 │  命中落地库 │
├─────────────┼───────────┼───────────┼───────────┼───────────┤
│  谋划→在谈  │ ✅ 正常升阶  │ ⚠️ 阶段倒退  │ ❌ 严重冲突  │ ❌ 严重冲突  │
│  在谈导入   │ ⚠️ 可能重复  │ ⚠️ 同阶段碰撞 │ ❌ 阶段倒退  │ ❌ 严重冲突  │
│  签约导入   │ ❌ 不合理   │ ❌ 阶段跳跃  │ ⚠️ 可能重复  │ ❌ 阶段倒退  │
│  落地导入   │ ❌ 不提供   │ ❌ 不提供   │ ❌ 不提供   │ N/A       │
└─────────────┴───────────┴───────────┴───────────┴───────────┘
```

**AI推理逻辑示例：**

```javascript
// 伪代码：AI判重决策树
function aiJudgeConflict(newProject, existingProject) {
  const nameSimilarity = calculateSimilarity(newProject.name, existingProject.name);
  const stageGap = getStageGap(newProject.stage, existingProject.stage);

  // 规则1: 名称完全相同 → 强冲突
  if (nameSimilarity === 1) {
    return {
      level: 'HIGH',
      reason: '项目名称完全相同',
      suggestion: stageGap > 0 ? '建议覆盖（阶段升阶）' : '建议合并或忽略'
    };
  }

  // 规则2: 名称相似+主体相同 → 高概率重复
  if (nameSimilarity >= 0.85 && newProject.investor === existingProject.investor) {
    return {
      level: 'MEDIUM',
      reason: `项目名称相似度${(nameSimilarity*100).toFixed(0)}%，投资主体一致`,
      suggestion: '请人工核对投资金额与进展信息'
    };
  }

  // 规则3: 阶段逻辑冲突（如在谈数据命中签约库）
  if (stageGap < -1) { // 倒退超过1个阶段
    return {
      level: 'WARNING',
      reason: `阶段状态不合理：试图将${newProject.stage}导入，但库中已存在${existingProject.stage}阶段`,
      suggestion: '建议忽略本条导入，保留库中原有数据'
    };
  }

  return null; // 无冲突
}
```

### 3.3 AI辅助文案模板库

为提升研判效率，预置**场景化建议话术**：

| 场景 | AI建议文案 | 推荐操作 |
|------|-----------|---------|
| 谋划→在谈升阶 | "该项目在谋划库中已存在，市级数据显示其已取得实质进展（签约意向书/投资协议），建议推进至在谈阶段并用最新数据覆盖。" | **覆盖（推荐）** |
| 同阶段数据碰撞 | "区级系统内已存在同名在谈项目，双方投资金额偏差15%，建议对比最新进展后决定是否合并。" | **合并覆盖 / 忽略** |
| 阶段倒退冲突 | "该项目已在签约阶段，本次导入的在谈数据相对滞后，可能导致阶段状态回退，建议忽略。" | **忽略（推荐）** |
| 投资主体相同+行业相同 | "虽然项目名称不同，但投资主体和产业类别完全一致，且投资金额接近，可能为同一项目的不同命名版本。" | **人工确认** |

## 四、界面交互设计

### 4.1 研判池列表页（主入口）

**页面路径**: `/project/yanpan`

**布局结构**:
```
┌─────────────────────────────────────────────────────────────┐
│  项目重复研判                                    待处理: 12条 │
├─────────────────────────────────────────────────────────────┤
│  [筛选] ▼  状态: [全部▼]  来源: [全部▼]  阶段: [全部▼]     │
│  [批量裁决] [导出报告]                                      │
├────┬──────────┬────────┬──────────┬────────┬────────┬───────┤
│ ☐  │ 新导入项目 │ 命中规则 │ 冲突对象  │ AI建议  │ 来源  │ 操作 │
├────┼──────────┼────────┼──────────┼────────┼────────┼───────┤
│ ☐  │ XX生物科技│ L1强匹配│ 在谈#123 │ 覆盖   │ 张三  │ [详情]│
│ ☐  │ YY新能源  │ L2高相似│ 签约#456 │ 忽略   │ 李四  │ [详情]│
│ ...│          │        │          │        │      │      │
└────┴──────────┴────────┴──────────┴────────┴────────┴───────┘
```

**核心字段说明**:
- **新导入项目**: 显示项目名称 + 当前阶段Tag（谋划/在谈/签约）
- **命中规则**: L1-L4等级标签 + 具体原因（如"L2: 名称相似92%+主体相同"）
- **冲突对象**: 库中已有项目的名称 + 编号（可点击跳转详情）
- **AI建议**: 一句话推荐操作（覆盖/忽略/合并）+ 置信度百分比
- **来源**: 导入人姓名 + 导入时间

**筛选维度**:
- 处理状态：`待处理` / `已裁决-覆盖` / `已裁决-忽略` / `已裁决-新项目`
- 冲突等级：`L1强匹配` / `L2高相似` / `L3中风险` / `L4弱提示`
- 目标阶段：`谋划` / `在谈` / `签约`
- 时间范围：导入时间区间

### 5.2 核心算法选型

| 功能模块 | 技术方案 | 选型理由 |
|---------|---------|---------|
| **文本相似度** | Sentence-BERT (中文预训练模型) | 比传统编辑距离更懂语义（"XX生物"≈"XX生物医药"） |
| **阶段冲突检测** | Drools规则引擎 | 业务规则频繁调整，规则外置便于维护 |
| **AI建议生成** | Prompt Engineering + GPT-3.5-turbo | 成本可控，效果满足场景需求 |

### 5.3 数据模型设计

CREATE TABLE yanpan_pool (
  id SERIAL PRIMARY KEY,

  updated_at TIMESTAMP DEFAULT NOW()
);

-- 字段级比对明细表
CREATE TABLE yanpan_field_comparison (
  id SERIAL PRIMARY KEY,

  new_value TEXT,                       -- 新值
  old_value TEXT,                       -- 旧值
  is_same BOOLEAN,                      -- 是否一致
  similarity_score FLOAT                -- 相似度分数（仅文本字段）
);

## 六、风险与应对

### 6.1 技术风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| AI误判导致漏报 | 重复项目入库污染数据 | 设置L1/L2为**强制阻断**（必须处理后才能继续导入），L3/L4仅警告 |
| 大量并发导入性能瓶颈 | 判重耗时过长影响用户体验 | 引入消息队列异步处理，前端轮询获取结果 |
| 文本相似度模型冷启动 | 初期准确率低 | 先用规则引擎兜底，积累1000+样本后再启用模型 |

### 6.2 业务风险

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 园区抵触判重机制 | 认为增加工作量 | 强调"减少后续返工"，并提供**一键覆盖**快捷操作 |
| 投促局裁决积压 | 研判池爆满 | 设置SLA（如24小时未处理自动升级提醒），支持**批量裁决** |
| 恶意绕过判重 | 手动拆分项目名称规避检测 | 增加**联系人电话/地址**等弱特征交叉验证 |

## 九、附录：术语表

| 术语 | 定义 |
|------|------|
| **研判池** | 存放所有待处理冲突项目的临时区域，类似"回收站"但用于数据仲裁 |
| **L1-L4** | 冲突严重程度分级，L1最高（必须处理），L4最低（仅提醒） |
| **覆盖** | 用新导入数据完全替换库中原有记录，适用于"新数据更准确"的场景 |
| **合并覆盖** | 智能融合两份数据，通常取各字段的最新值，同时保留历史进展记录 |
| **阶段升阶** | 项目从低阶段向高阶段流转（谋划→在谈→签约→落地），属于正常业务行为 |
| **阶段倒退** | 项目从高阶段退回低阶段（如签约→在谈），属于异常情况需重点核查 |
